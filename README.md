# Xray Torrent Guard

Собственный движок обнаружения и блокировки BitTorrent-трафика для VPN/прокси-серверов
(Xray/VLESS, Hysteria и др.). Открытый код для владельцев VPN- и прокси-узлов.

> Статус: release candidate (v0.1.0-rc.1). Проверено на изолированном стенде (`testbed/`) и синтетической нагрузке, на боевых нодах — пока нет.

## Зачем

- Жалобы правообладателей и хостеров приходят на IP ноды, а страдает весь сервис.
- Существующие средства (sniffing `bittorrent` в Xray, торрент-блокер Remnawave, `ipp2p`)
  опознают только открытый handshake: шифрованный BT (MSE/PE), uTP и DHT проходят мимо.

## Подход

Xray Torrent Guard — самостоятельный демон на ноде, не обёртка над чужими блокерами:

1. **Свой анализатор протоколов**: BT handshake, MSE/PE, uTP, DHT (bencode KRPC), трекерные
   announce (HTTP/UDP), LSD, PEX.
2. **Поведенческие эвристики** на пользователя: веер пиров и UDP-потоков, порты DHT,
   симметрия трафика, всплески коротких соединений.
3. **Оценка риска**: сильные сигналы (handshake, DHT, трекер, LSD) сразу дают событие,
   слабые (uTP, кандидат MSE, веер UDP-пиров) суммируются в скользящем окне.
4. **Открытый выход вместо готовых интеграций**: HTTP API, webhook и внешняя команда.
   Блокировку, бан и уведомления каждый подключает под свою панель и фаервол сам.

Сторонние решения используются только как эталон для сравнения на стенде.

## План

1. Стенд: qBittorrent, Transmission, libtorrent; шифрование вкл/выкл, uTP, DHT, magnet.
2. Замер, что ловят существующие средства — точка отсчёта.
3. Анализатор и эвристики, тесты на записанном трафике (pcap).
4. Примеры обработчиков (бан через API панели, nftables), Docker-образ.
5. Упаковка: Docker-образ, скрипт установки, документация, лицензия MIT.

## Принципы

- Никаких данных пользователей в репозитории и логах по умолчанию.
- Работает на типовой VPS (1 vCPU, 1 ГБ).
- Каждое утверждение «ловит/не ловит» подтверждено воспроизводимым тестом.

## Сборка и запуск

Rust ≥ 1.80, внешних зависимостей нет (на Linux — только `libc`).

```bash
cargo build --release          # target/release/xtg, ~350 КБ
cargo test
```

```bash
xtg analyze capture.pcap                       # события в stdout (JSON Lines)
sudo xtg run --iface wg0 --api 127.0.0.1:9090  # живой захват, Linux
xtg run --iface tun0 --exec 'nft add element inet filter banned { $XTG_SUBJECT }'
```

Без лога субъект — IP инициатора потока (подходит для TUN/WireGuard).

## Xray: события по пользователям

На внешнем интерфейсе ноды все исходящие потоки идут с IP сервера. `xtg` читает
access-лог Xray и по адресу назначения находит, какой пользователь открыл поток:

```
2024/05/05 12:00:00 from 1.2.3.4:5678 accepted udp:5.6.7.8:6881 [vless-in >> direct] email: alice
```

Пакет ноды к `5.6.7.8:6881` в ближайшие секунды считается трафиком `alice`.

```bash
sudo xtg run --iface eth0 --xray-log /var/log/xray/access.log --only-attributed   --exec 'curl -s -X POST http://127.0.0.1:8000/my-ban-hook -d "$XTG_SUBJECT"'
```

Что нужно в конфиге Xray:

- `"log": {"access": "/var/log/xray/access.log"}`;
- у клиентов задан `email` (панели обычно ставят туда имя пользователя);
  без email субъектом станет IP клиента из поля `from`.

Ограничения:

- если sniffing подменил адрес на домен (`destOverride` без `routeOnly`), строку нельзя
  сопоставить с пакетом; таких строк видно по счётчику `domain_lines` в `/health`.
  Пиры BitTorrent ходят по IP, так что основной трафик сопоставляется;
- если два пользователя одновременно ходят на один и тот же `IP:порт`, берётся тот,
  чья строка в логе ближе к началу потока;
- `--only-attributed` отбрасывает потоки без строки в логе (служебный трафик ноды);
- лог ротируется (`logrotate`) — `xtg` переоткрывает файл сам.

Для `analyze` лог читается целиком, время берётся из строк; если Xray пишет местное
время, укажите `--log-utc-offset +03:00`.

## Установка на ноду

```bash
cargo build --release
sudo sh deploy/install.sh            # бинарник, systemd-юнит, /run/xray в tmpfs
sudoedit /etc/default/xtg            # интерфейс, обработчик событий
sudo systemctl enable --now xtg
curl -s 127.0.0.1:9090/health
```

Или Docker-образ (~2 МБ, `FROM scratch`): `docker build -t xtg .`, запуск с
`--network host --cap-add NET_RAW -v /run/xray:/run/xray`.

### Объём access-лога

Xray пишет строку на каждое соединение. Торрент-клиент открывает их тысячами, так что
при десятках качальщиков лог растёт на гигабайты в час. Поэтому:

- лог кладётся в `/run/xray` (tmpfs): на диск не пишется, после перезагрузки пуст;
- `--xray-log-max 64M`: прочитав 64 МБ, `xtg` сам усекает файл до нуля. Xray открывает
  лог с `O_APPEND` и продолжает писать с начала, перезапуск не нужен. Строки, записанные
  в миг усечения, теряются (единицы); лог в tmpfs никогда не превысит лимит заметно;
- внешний `logrotate` тоже поддерживается: после ротации новый файл читается с начала.
  Если используете его, ставьте `copytruncate` — Xray не переоткрывает лог сам;
- `loglevel: warning` — отладочные строки `xtg` не нужны.

Юнит ограничен: только `CAP_NET_RAW` и `CAP_DAC_OVERRIDE`, запись разрешена лишь в
`/run/xray`, `MemoryMax=256M`, `CPUQuota=50%`. Потери пакетов ядром при нехватке CPU
видны в `/health` (`kernel_drops`) и в журнале.

## API

| Запрос | Ответ |
|---|---|
| `GET /health` | `{"status":"ok","version":"…","packets":N,"xray":{…}}` |
| `GET /v1/events?since=ID` | события с `id > ID` (последние 1000; с `--events-file` сохраняются между перезапусками) |
| `GET /v1/subjects` | текущие оценки субъектов |

Событие:

```json
{"id":1,"ts":1700000001.000000,"type":"torrent_detected","subject":"alice",
 "subject_kind":"user","score":100,"proto":"udp","remote":"87.98.162.88","reasons":{"dht":1}}
```

`--webhook http://…` шлёт тот же JSON POST-запросом, `--exec CMD` запускает команду с
переменными `XTG_SUBJECT`, `XTG_SUBJECT_KIND` (`user`/`ip`), `XTG_SCORE`, `XTG_REMOTE`, `XTG_REASONS`, `XTG_EVENT`.
API без авторизации — слушайте только `127.0.0.1`.

## Что ловится сейчас

| Сигнал | Вес | Чем подтверждено |
|---|---|---|
| BT handshake (TCP и внутри uTP) | 100 | юнит + стенд |
| DHT KRPC (с проверкой bencode) | 100 | юнит + pcap-тест |
| HTTP announce/scrape | 100 | юнит + стенд |
| UDP-трекер (BEP 15) | 100 | юнит-тест |
| LSD (BEP 14) | 100 | юнит-тест |
| uTP-заголовок (кроме STUN) | 20/пир, до 100 | юнит + стенд |
| Кандидат MSE/PE (кроме портов 443, 80, 22…) | 10/пир, до 100 | юнит + стенд |
| Веер UDP ≥ 40 пиров/мин | 50 | юнит-тест |
